# SupplyGuard：AI 编程时代的多 Agent 供应链安全守门员

## 作品简介（498 字）

**SupplyGuard** 是一套面向 AI 编程时代的多 Agent 供应链安全防御系统，聚焦企业软件依赖从"引入"到"爆发"两个关键风险时刻，让 Agent 自动完成检测、分析、决策、修复、验证、审计的全闭环。

**问题与场景**：Copilot、Cursor、Claude Code 等 AI 编程工具大幅提升了编码效率，却也带来了新攻击面——LLM 会"幻觉"出并不存在的包名，攻击者抢注这些名字（slopsquatting），让恶意包随 PR 进入代码库。传统 SCA 工具（Snyk、Dependabot）只扫描告警、不参与决策，零日事件爆发后仍需人肉救火。中小团队尤其缺乏轻量、可自托管、能闭环修复的智能方案。

**核心解决方案**：SupplyGuard 采用"双入口一引擎"架构。守门模式在 PR 时刻拦截 AI 幻觉包、typosquatting、CVE、license 冲突；响应模式在 CVE / 恶意包披露后自动完成全库影响面评估与修复 PR 生成。系统由 Sentinel（协调）、Analyst（分析）、Remediator（修复）、Auditor（审计）四个 Agent 组成，以 AgentTeams（HiClaw）为协同框架，通过 13 个可复用 Skill 调用 MCP 工具完成工作。

**创新点与差异化**：1）原生防御 prompt injection 的七层"洋葱"安全架构——Agent 读取的恶意包内容可能反过来攻击 Agent 自身，这是传统 SCA 工具无需面对却被现有 Agent 系统忽视的元级风险；2）从"告警"到"闭环修复"的最后一公里，修复后自动沙箱测试并回滚失败补丁；3）AI 时代独有的 slopsquatting 检测与处置能力。

**开放 / 复用价值**：Skill 层设计为可复用任务能力抽象，底层 SBOM、包画像、修复策略可被守门 / 响应两模式共享；Agent Identity 与 MCP 接入契约结构化，后续可迁移至任何多 Agent 框架。

**当前进展**：已完成方案设计、4 Agent 分工、13 Skill 清单、技术选型与可运行骨架代码；slopsquatting 拦截 Demo 已跑通，可自动识别 `lodos` 等 typosquat 包并输出 block 裁决与审计日志。
